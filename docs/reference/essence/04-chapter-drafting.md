# 4. 章単位の逐次執筆と長さ管理

## 逐次生成の原則

章本文は**並列ではなく1章ずつ順番に生成**する。理由は連続性: 各章のプロンプトに前章までの成果を含めるため、前章の完了が次章の入力になる。

章プロンプトのコンテキスト:

- 全章のアウトライン圧縮ビュー+対象章の詳細(keyEvents 最大5、foreshadowing 最大3)
- **前章までの chapterSummary**(要約の連鎖で長編の文脈を保つ)
- **直前章の結末抜粋**(英語なら末尾 ~100語、日本語なら末尾 ~300字)— 章間の接続を滑らかにする

各章の生成成功時に draft と同時に **chapterSummary と continuityNotes を保存**する。これが次章のコンテキストと最終監査の入力になる。

## 長さ管理

- 長さの単位は言語で決める: **日本語=文字数(空白除去後)、英語=単語数(空白区切り)**。同じ数値でも意味が変わるため、単位を混在させない。
- 章ごとに lengthPlan(target / unit / min / max)を持つ。min/max は target の **85% / 115%**。
- プロンプトでは target の 90% を minimum、120% を preferred maximum として指示(±20% は pacing guidance であり厳密な切り詰め条件ではない)。
- 総量指定は整数除算で各章へ均等配分し、余りを先頭章から1ずつ加える。

### 3つの閾値の意味を区別する

| 閾値 | 意味 |
|---|---|
| 75% 未満 | 生成直後に**自動で拡張 API を1回**呼ぶ |
| 拡張後 85% | 到達すれば解決。未達なら needsExpansion=true+警告を残し、手動拡張を促す |
| 85–115% | 表示上の「near」帯域(下回れば under / too-short、上回れば over) |

75% 以上なら自動拡張はせず、too-short 判定だけ残して手動操作に委ねる。

## 章の選択・スキップ・再開

章の選択ロジックは1箇所に集約し、UI 側で独自の番号順を実装しない。

- **生成対象**: draft が無い章は常に対象。オプションで failed / too-short も対象に含める。forceRegenerate はすべての保護を外す。
- **スキップ条件**: 「十分な長さの draft があり、状態が completed または edited」の章だけスキップ。draft があっても failed / too-short / needsExpansion なら再生成対象。
- **次の章**: 番号昇順で最初の未完成章。
- 同一実行内の重複選択は試行済み集合(attemptedChapters)で防ぐ。

## 失敗時の継続ポリシー

- **単章生成**: stopOnFailure=true。失敗したら即座に止めてユーザーに返す。
- **残り一括生成/再開**: stopOnFailure=false。失敗章を failed として記録し、**次の章へ進んで独立した成功を積み上げる**。
- 失敗章は削除せず再試行対象として残す。再生成のターゲット選択は failed → missing → 次の未完成章の優先順。
- 中断(abort)は失敗と区別する。中断された章は cancelled として記録し、再開時は新しい AbortController で途中状態から続行する。

## 完了判定と最終化

- 章がすべて揃ったかは「期待章数に対する draft 保有章数(coverage)」で判定する。成功レスポンスの回数ではなく**実際に本文がある章**を数える。
- 全章完了後、章構造から原稿(manuscript)を**再構築**してから仕上げ段(editor 以降)へ進む。stale な原稿を後段に渡さない。
- 第1章のタイトルが生成され、プロジェクトが未命名のままなら、それを仮タイトルに昇格する(第2章以降では変更しない)。最終的なタイトルは publisher の titleIdeas 先頭で上書きされる。

## タイムアウトと事前警告

- 章生成・拡張には壁時計タイムアウトを設け、タイムアウト文には章番号と「章長を減らす/モデルを変える」等の対処助言を含める。
- 言語別に「長すぎる章」の事前警告閾値を持つ(参考値: 日本語 8,000字、英語 3,000語)。これは拒否ではなく警告で、入力自体は通す。
